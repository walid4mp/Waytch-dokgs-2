# Neon Cipher — Architecture & SOLID

A clean, layered project that survives growth. This document is the contract for contributors.

## 1. Layers (inward-allowed dependencies)

```
        UI / PhoneUI / HudController        (UI Toolkit / UGUI / IInputProvider)
        ↑
   Mission / Inventory / Hacking / PhoneUI / Saving  (game domain — pure C# where possible)
        ↑
   Player / Vehicle / NPC / Traffic / World / Audio  (engine-facing adapters)
        ↑
   Core  — GameServices + interface contracts
```

The Core layer has zero engine references outside the interfaces; the
domain layer (Mission / Inventory / Hacking) has no `MonoBehaviour`
references — every gameplay rule is testable headless.

## 2. SOLID — concrete touch points

| Principle | Where it lives |
|---|---|
| **S**ingle Responsibility | One MonoBehaviour per concern. `PlayerController` moves the player; it does not also handle save load or weather. |
| **O**pen/Closed | New devices implementing `IHackable` plug into `HackingBus.RunHack` without modifying the bus. |
| **L**iskov | `EyeHackableCamera`, `CypherLockable`, `SignalOverrideableLight`, `SwarmHackableDrone`, `GridTapableAlarm`, `ConsoleBreachableTerminal` all satisfy `IHackable` and may be passed to `HackingBus`. |
| **I**nterface Segregation | `IWorldClock`, `IGameSettings`, `ISaveSystem`, `ILocalization`, `IAudioBus`, `IWeather`, `IHackingBus` are split into separate contracts — no fat interface. |
| **D**ependency Inversion | `GameBootstrap` is the only place that constructs implementations; everything else depends on interfaces resolved via `GameServices`. |

## 3. Composition root

`Source/Core/GameBootstrap` is the only file that touches concrete classes
during wiring. Replace the order to produce test rigs (e.g. swap
`SaveSystem` for `FakeSaveSystem` in `EditMode` tests).

## 4. Folder conventions

* `/Source/<System>` — runtime C# for that system.
* `/Assets/<MirroredName>` — Unity-managed mirror (audio, URP, Localization
  tables). Anything imported from the asset store lives here.
* `/Assets/Scenes` — Unity scenes.
* `/Documentation/<Kind>` — design / API / compliance notes.
* `/BuildScripts/Android` — Gradle template (generated by Unity).

## 5. Performance on Android

| Item | Decision |
|---|---|
| Render pipeline | URP (single-pass forward, MSAA off, post-processing stack limited to Bloom + Vignette) |
| Shader variant stripping | enabled (Build Settings → Player → Other → Strip unused). |
| Texture compression | ASTC 6×6 (most phones from 2018 onward) |
| Mesh LOD | `LODGroup` 0/1/2 with Culled@40m |
| Physics | Self-driven circle colliders on player + sphere cast on guard sight; over 30 agents → navMeshObstacle pooling |
| Streaming | `WorldStreaming` chunks 9 active out of N; async additive load / unload |
| GC | Pre-allocated `Dictionary`, reuse of `List<T>`, `Task` not awaited in hot paths |
| Battery | 60 FPS cap by default, 30 FPS fallback when battery < 20 % via `Application.batteryStatus` |

## 6. Test pyramid

* **Edit-mode** (NUnit + Unity TestRunner) — pure C# domain (50 ms).
  * Save / Load round trip
  * Mission progress + rewards
  * Localization fallback
  * Hacking bus criteria

* **Play-mode** — additive scene load + 1-second input trace replay.

* **CI artefacts** — Test reports uploaded every PR.

## 7. Adding a new hackable device

1. Implement `IHackable` on a new MonoBehaviour.
2. Add its prefab to the streaming chunk you want.
3. (Optional) Update the `HackType` enum + add a localized name to every
   table in `/Assets/StreamingAssets/Localization/`.
4. Add a `FakeHackable` test variant under `Assets/Tests/EditMode/`.
No changes to `HackingBus` are needed.

## 8. Adding a new mission

1. Create `MissionSO` asset (Right-click → Create → Neon Cipher → Mission).
2. Fill `Steps[]` with `Step` entries (each with `ObjectiveWorldPos`).
3. Place `MissionTrigger` colliders at each objective.
4. `MissionController.Register` from gameplay glue.
5. Trigger UI through `HudController` listening to `MissionController`.

## 9. Localization workflow

Tables live as JSON in `Assets/StreamingAssets/Localization/<iso>.json`.
Adding a key requires:

* Adding the entry to **all** ISO files (en, fr, ar, ja).
* Running `Window → Asset Management → Localization Tables → Update Asset Tables`.
* In code, always call `loc.T("key")` — never hard-code user-facing strings.

## 10. Settings & save safety

`GameSettingsService.SerializeToDisk()` happens on `OnApplicationPause(true)`
and on every key change. `SaveSystem.Save(...)` is AES-CBC encrypted with
PBKDF2-derived key from a salt + current language; this keeps saves
unique per language without persisting secrets.

Settings, saves, save backups, language and controls are all under
`Application.persistentDataPath`. Backup rules in
`Assets/Plugins/Android/backup_rules.xml` includes only the `saves/`
subfolder (no cache, no telemetry).
